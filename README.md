# Foundry Appliance

A virtual appliance for building cyber labs, challenges and competitions

## Overview

Foundry Appliance is a virtual machine that integrates cyber workforce development apps from the [Software Engineering Institute](https://www.sei.cmu.edu) at [Carnegie Mellon University](https://www.cmu.edu).

This project builds the virtual appliance using Ubuntu and [K3s](https://k3s.io/)&mdash;a lightweight Kubernetes environment. Pre-built OVA images are also available under [Releases](https://github.com/cmu-sei/foundry-appliance/releases).

## Getting Started

After [deploying the appliance](#deploying-the-appliance), visit https://foundry.local to begin using the apps. Or login using the VM console:

```
username: foundry  
password: foundry
```

## Deploying the Appliance

### ESXi Host

You can deploy the appliance to a standalone ESXi host using either:

1. **One-step process** - `import-appliance.sh` (downloads and imports automatically)
2. **Two-step process** - `download-ova.sh` + `import-ova.sh` (required for ESXi free license)

#### Option 1: One-Step Process (Recommended)

**Quick deployment via curl:**
This can be run from any Linux or macOS host with network access to your ESXi server:

```bash
curl -sSL https://github.com/sei-noconnor/foundry-appliance/HEAD/import-appliance/import-appliance.sh | \
  GOVC_URL=your-esxi-host.com \
  GOVC_USERNAME=root \
  GOVC_PASSWORD='your-password' \
  GOVC_DATASTORE=datastore1 \
  bash
```

**Local deployment:**
```bash
# Set ESXi connection details
export GOVC_URL=https://your-esxi-host.com
export GOVC_USERNAME=root
export GOVC_PASSWORD=your-password
export GOVC_INSECURE=true
export GOVC_DATASTORE=datastore1

# Deploy the OVA (automatically downloads latest release)
./import-appliance.sh
```

#### Option 2: Two-Step Process

**Required for ESXi free license users** or when you want more control over the download and import process:

**Step 1: Download and Process OVA**

```bash
# Download latest release and process for ESXi compatibility
./download-ova.sh [ova_url] [output_dir]

# Examples:
./download-ova.sh                                    # Downloads latest release to ./output/
./download-ova.sh ./custom-output/                   # Downloads to custom directory
./download-ova.sh https://example.com/custom.ova     # Downloads specific OVA
```

**Step 2: Import to ESXi**

```bash
# Set ESXi connection details
export GOVC_URL=your-esxi-host.com
export GOVC_USERNAME=root
export GOVC_PASSWORD='your-password'
export GOVC_INSECURE=true
export GOVC_DATASTORE=datastore1

# Import the processed OVA
./import-ova.sh [options] <ova_file> [vm_name] [resource_pool]

# Examples:
./import-ova.sh ./output/foundry-appliance-v0.10.2.ova                    # Basic import
./import-ova.sh -f ./output/foundry-appliance-v0.10.2.ova                 # Force replace existing VM
./import-ova.sh -a ./output/foundry-appliance-v0.10.2.ova                 # Auto-rename if VM exists
./import-ova.sh ./output/foundry-appliance-v0.10.2.ova my-custom-name     # Custom VM name
```

**Import Options:**

- `-f, --force` - Remove existing VM if it exists and replace it
- `-a, --auto-rename` - Automatically generate a unique name if VM exists (e.g., `foundry-appliance-v0.10.2-1`)
- `-h, --help` - Show detailed help and usage examples

**What the scripts do:**

`download-ova.sh`:

- Downloads the latest Foundry appliance OVA from GitHub releases
- Removes incompatible sound card hardware for ESXi compatibility
- Updates manifest checksums
- Caches downloads for faster subsequent runs

`import-ova.sh`:

- Validates ESXi connection and credentials
- Handles existing VM conflicts with flexible options
- Extracts and imports the OVA to your ESXi host
- Powers on the VM automatically after successful import

**Prerequisites:**

- [govc](https://github.com/vmware/govmomi/tree/main/govc) must be installed (auto-installed if missing)
- Network connectivity to your ESXi host
- DHCP and internet access
- Valid ESXi credentials with administrative privileges

**Note for ESXi Free License Users:**

ESXi free license restricts programmatic OVA imports. If you encounter license errors with `import-ova.sh`, use the ESXi web interface to manually import the processed OVA file generated by `download-ova.sh`. This is why the two-step process is recommended for free license users.

## Build

To build the appliance, you will need:

- [Packer](https://www.packer.io/) 1.7+
- A compatible hypervisor:
  - [VirtualBox](https://www.virtualbox.org/) (`virtualbox`)
  - [Proxmox Virtual Environment](https://www.proxmox.com/en/products/proxmox-virtual-environment/overview) (`proxmox`)

### Proxmox Build (optional)

To build the appliance using Proxmox, create a file named `proxmox.auto.pkrvars.hcl` in this directory and add these settings:

```hcl
proxmox_url      = "https://<proxmox.fqdn>:8006/api2/json" # replace with your PVE server
proxmox_user     = "root@pam"
proxmox_password = "<password>"
proxmox_node     = "pve.lan" # replace with the Proxmox node name that should build the appliance
```

### Build Script

Run the following command, where `<hypervisor>` is a comma-delimited list of target hypervisors:

```bash
./build-appliance.sh <hypervisor>
```

For example, to build the appliance with VirtualBox, run this command:

```bash
./build-appliance.sh virtualbox
```

To add Proxmox to the previous build, run this command:

```bash
./build-appliance.sh virtualbox,proxmox
```

[Packer `build` options](https://www.packer.io/docs/commands/build) can be appended to the end of the command. For example, this will save partial builds and automatically overwrite the previous build (useful for debugging):

```bash
./build-appliance.sh <hypervisor> -on-error=abort -force
```
